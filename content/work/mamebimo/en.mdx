## Context

Mamebimo is an Everest-adjacent product: a Dakar marketplace that connects households with verified providers for home cleaning and at-home cooking. I owned the web app end-to-end — booking, messaging, payouts-oriented flows, and admin operations — on a PWA-ready React + Supabase stack.

## Problem

Local service marketplaces fail when trust and ops are afterthoughts. Households need verified providers and clear booking states; providers need payouts and messaging that work on mobile networks. A pretty listing page without an ops spine does not survive first contact with reality.

## Approach

- **Supabase as the operational core** — Postgres, Auth, and Edge Functions for booking and messaging paths.
- **French-first UI** with English via i18next — matches how Dakar households and providers actually communicate.
- **Admin ops from day one** — provider review and booking oversight, not bolted on after launch.

## Outcome

Marketplace shipped at [mamebimo.com](https://mamebimo.com). Admin route placeholder marked `*` until the public path is confirmed.

## Lessons

**Marketplace trust is an ops product.** Verification, messaging, and payouts are the product; the listing grid is packaging.

**Everest-adjacent work still needs solo ownership.** Referral origin does not reduce the need for a clear operating model.
